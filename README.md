# Engineering Field Guide

Software-engineering concepts explained visually, for quick daily reference and for learning or
interview prep. Self-paced: no levels, no schedules. A static site built with Astro, MDX and React
islands (TypeScript), deployed to GitHub Pages. It installs as an app and works fully offline.

Working on this repo, or handing it to an agent? Read [`AGENTS.md`](AGENTS.md) first. Agreed work
and its order are in [`BACKLOG.md`](BACKLOG.md).

## What's in it

- **13 tracks, 165 topics:** CS foundations, DSA, Java and runtimes, concurrency, OOP and design
  patterns, low-level design, backend, databases, system design, distributed systems, DevOps,
  AI engineering, interviews and career.
- **Every topic** opens with a Quick Reference card, then explains the idea with an analogy,
  diagrams, step-by-step walkthroughs (each with a colour key), code in Java, JavaScript and Python
  tabs, trade-off tables and charts, pitfalls, and an interview section with questions, follow-ups,
  practice and a quiz.
- **Company tags:** "Reported in interviews at …", built from public interview reports, each linked
  to its source. Browse them by company at `/companies/`.
- **Glossary** terms show their definition on hover or tap; the full list is at `/glossary/`.
- **Cheat sheets** collect every Quick Reference card of a track on one printable page.
- **Search** (`/` or `Ctrl/⌘ K`), light and dark themes, reading mode (hides both side panels),
  code wrap, a remembered code language.
- **Progress and bookmarks** saved in the browser, with a `/progress/` page.
- **Review** (`/review/`): quiz answers are remembered per question. Missed questions come back
  straight away; right ones come back after 1, 3, 7, 16 and 35 days (spaced repetition). Rounds
  of 10, filterable by track, with new questions optionally limited to topics you've completed.
- **Offline app:** the first visit saves the whole site (about 68 MB). Updates download only changed
  files and ask before switching. The `/offline/` page checks for updates, repairs missing files,
  re-downloads everything, removes the copy, and explains how to install the app.

## Run it

```bash
npm install
npm run dev            # http://localhost:4321/engineering-field-guide/
npm run build          # static site, search index and service worker in dist/
npm run preview        # serve dist/ (the offline app only runs in a build, not in dev)
```

Requires Node 22+. The diagram, icon, OG-image and audit scripts use Playwright:
`npx playwright install chromium`.

## npm scripts

| Script | What it does |
|---|---|
| `dev` | Dev server with hot reload. The service worker is disabled in dev. |
| `build` | `astro build`, then `pagefind` (search index), then `scripts/pwa/build-sw.ts` (writes `dist/sw.js` with a hash of every file). |
| `preview` | Serves the built site. |
| `lint` | ESLint. |
| `check` | `astro check` plus a typecheck of `scripts/`. |
| `check:content` | Content checks Zod can't express: missing or orphan snippets, diagrams and walkthroughs; duplicate ids; broken topic links; glossary ids; `askedAt` sources; walkthrough legends; leftover level/schedule wording; missing OG cards. |
| `format` | Prettier. |
| `new:topic -- <track>/<slug> "Title"` | Scaffolds a topic folder from the template. |
| `diagrams` | Renders Mermaid `.mmd` files to themed `.svg`. `-- --check` fails if any are stale (CI runs this). |
| `og` | Renders the Open Graph card for each track into `public/og/`. |
| `icons` | Renders the app icons into `public/icons/`. |
| `audit:mobile` | Opens every built page at 360px; fails on horizontal page scroll, reports small targets and text. Needs `npm run preview` running. |
| `audit:offline` | Lets the service worker save the site, goes offline and opens every page; fails if any page or request isn't served from the saved copy. Needs a preview. |
| `test:offline-update` | Tests the update flow end to end: 404 offline, update prompt, reload, repair, re-download, check for updates. Needs a preview. |
| `research:fetch`, `research:analyze`, `research:apply` | The interview-report research pipeline (see `research/README.md`). |
| `report:migration` | Legacy migration coverage report (kept for reference). |

The audits use `http://localhost:4321/engineering-field-guide/`; set `PREVIEW_URL` to use another.

## How content is organised

Content is stored as data, never as page HTML:

```
src/content/
├─ tracks/<track>.yaml                 # a track: title, short label, blurb, order, icon
├─ glossary/<term>.yaml                # term, short definition, optional topic link
├─ reports/<track>/<slug>.yaml         # generated by research:apply; don't edit by hand
└─ topics/<track>/<slug>/
   ├─ index.mdx                        # frontmatter + prose
   ├─ qa.yaml                          # questions, follow-ups, practice, quiz
   ├─ code/<id>.java|.js|.py|…         # one snippet = one file per language
   ├─ diagrams/<id>.svg | <id>.mmd     # hand-drawn SVG or Mermaid source
   └─ walkthroughs/<id>.yaml           # step-by-step visual frames
```

Schemas live in `src/content.config.ts`. A missing field, a wrong type or a reference to a topic
that doesn't exist fails the build.

### Add a topic

```bash
npm run new:topic -- distributed-systems/consistent-hashing "Consistent Hashing"
```

This scaffolds the standard template and marks the topic `draft: true`, which keeps it out of
production builds until you delete that line. Topics follow the same shape:

1. Quick reference, written in frontmatter (`quickRef`)
2. Why it matters, with an analogy
3. The core idea, with a diagram
4. How it works, as a walkthrough or steps
5. Implementation in code tabs
6. Trade-offs, as tables or charts
7. In production, with pitfalls
8. Key takeaways
9. The interview section, generated from `qa.yaml`

Frontmatter: `title`, `summary` (max 240 characters), `track`, `order`, `tags`, `aliases` (extra
search words), `prerequisites` and `related` (topic ids, checked), `quickRef`, `askedAt`,
`lastReviewed`, `draft`.

### Components available in MDX (no imports needed)

| Component | Use |
|---|---|
| `<CodeTabs id="x" title="…" />` | Every `code/x.*` file as language tabs, in the order of `codeLanguages` in `src/site.config.ts` (Java, JavaScript, Python, …). |
| `<Diagram id="x" caption="…" />` | Inlines `diagrams/x.svg`; tap to open the full-screen viewer. |
| `<Walkthrough id="x" />` | Step-through player for `walkthroughs/x.yaml`. |
| `<Chart type="bar\|line" … />` | Small build-time SVG chart. |
| `<DecisionGuide title="…" steps={[[question, answer]]} otherwise="…" />` | A yes/no decision ladder that reads well on a phone. |
| `<Callout type="note\|tip\|warning\|insight\|analogy\|prereq\|spot">` | Asides. |
| `<Steps>`, `<Pitfalls>`, `<KeyTakeaways>` | Wrap a Markdown list. |
| `<Term id="x">text</Term>` | Inline glossary definition. |
| `<Clues>`, `<PatternClues />` | DSA pages: the wording clues that point to a pattern. |

Snippet, diagram and walkthrough ids are global, so keep them unique (prefix them with the topic,
e.g. `lru-…`).

### Add a code language

Drop `code/<id>.<ext>` next to the existing files. For a language the site doesn't know yet, add it
to `codeLanguages` in `src/site.config.ts`. `<id>@<lang>.<ext>` is a per-stack variant (for example
one Dockerfile per runtime).

### Add a walkthrough

Write `walkthroughs/<id>.yaml` with `title`, `legend` and `frames` (each a `caption` and `panels`),
then place `<Walkthrough id="<id>" />` in the topic. The `legend` must label exactly the colours
(`tone`s) the frames use; `check:content` enforces it. See `AGENTS.md` for what each tone means.

### Add a diagram

- Hand-drawn SVGs must use the `--d-*` colour variables (see `src/styles/tokens.css`) so they work in
  both themes.
- Mermaid sources (`.mmd`) are rendered by `npm run diagrams`, and the generated `.svg` is
  committed. CI runs `npm run diagrams -- --check` to catch stale renders.

### Add a glossary term

Create `src/content/glossary/<id>.yaml` with `term`, `short` (max 220 characters) and optionally
`topic`. Use it in prose as `<Term id="<id>">words</Term>`.

### Company tags

`askedAt` on a topic or question records where a candidate publicly reported being asked it. Every
entry needs a `source` URL. Report data from the research pipeline lives in `src/content/reports/`.
Both feed the `/companies/` pages.

## Offline app

`npm run build` writes `dist/sw.js`, which lists every built file with a content hash. The first
visit saves all of them; later versions re-download only files whose hash changed, then a prompt
offers to reload. Updates are checked on each page open while online, when you return to the tab
after 10 minutes, and from the Offline page. Details are in `AGENTS.md`.

## Checks and deploy

```bash
npm run lint
npm run check
npm run check:content
npm run diagrams -- --check
npm run build
```

The GitHub Actions workflow in `.github/workflows/deploy.yml` runs all of these, builds, and deploys
to Pages on every push to `main`. In the repository settings, set **Pages → Source** to
**GitHub Actions**. The repository name and base path are set in `src/site.config.ts`.
