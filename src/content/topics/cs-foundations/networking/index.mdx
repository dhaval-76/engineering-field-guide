## Why it matters

Every request your service handles crosses a network, and many production problems are network problems in disguise: slow first requests (no connection reuse), timeouts under load (exhausted ports or pools), "works by IP but not by name" (DNS), or a mobile app that's slow only on poor connections (round trips). Knowing what each layer does tells you where time goes and which knob to turn.

<Callout type="analogy">
Sending a parcel: the street address is the IP address, the flat number is the port. The postal service (IP) moves boxes but may lose or reorder them; a courier with signatures and tracking (TCP) guarantees every box arrives, in order. A sealed, tamper-evident box is TLS. The courier's company phone book is DNS.
</Callout>

## The layers you actually deal with

| Layer | Protocols | What it gives you |
|---|---|---|
| Application | HTTP, gRPC, WebSocket, DNS, SMTP | meaning: requests, responses, messages |
| Security | TLS | encryption, server identity, integrity |
| Transport | TCP, UDP, QUIC | process-to-process delivery; reliability (TCP/QUIC) |
| Network | IP (v4/v6) | host-to-host routing across networks |
| Link | Ethernet, Wi-Fi | delivery on the local network |

## TCP vs UDP

| Aspect | TCP | UDP |
|---|---|---|
| Connection | handshake, then a stream | none — independent datagrams |
| Reliability | retransmits lost data, ordered | none (the app decides) |
| Flow/congestion control | yes | no (the app must be polite) |
| Overhead | higher, plus head-of-line blocking | minimal |
| Used by | HTTP/1.1, HTTP/2, databases, most APIs | DNS, video/voice, games, QUIC (HTTP/3) |

TCP keeps a connection per (source IP, source port, destination IP, destination port); a client opening and closing connections rapidly can exhaust ephemeral ports (TIME_WAIT). Connection pools and keep-alive avoid both the handshakes and the churn ([Connection pooling](../../backend/connection-pooling/)).

## HTTP versions

| Aspect | HTTP/1.1 | HTTP/2 | HTTP/3 |
|---|---|---|---|
| Transport | TCP | TCP | QUIC over UDP |
| Requests per connection | one at a time (browsers open ~6) | many, multiplexed streams | many, independent streams |
| Headers | text | compressed (HPACK) | compressed (QPACK) |
| Head-of-line blocking | per connection | at the TCP level (one lost packet stalls all streams) | none across streams |
| Handshake | TCP + TLS | TCP + TLS | combined, 1 RTT (0-RTT resumption) |

<Term id="grpc">gRPC</Term> runs on HTTP/2; <Term id="websocket">WebSockets</Term> upgrade an HTTP/1.1 connection (or use HTTP/2 extended CONNECT) into a long-lived bidirectional channel.

## DNS

Resolution walks from your resolver's cache to root, TLD and authoritative servers; answers are cached for their **<Term id="ttl">TTL</Term>** at every level. Lower TTLs before a migration; expect clients and JVMs to cache longer than you'd like (Java caches successful lookups — set `networkaddress.cache.ttl` sensibly). DNS-based load balancing and failover are only as fast as the TTLs allow.

## Load balancers and proxies

- **L4** (TCP/UDP): routes connections by address and port; fast, protocol-agnostic; can't see HTTP paths.
- **L7** (HTTP): terminates TLS, routes by host/path/header, retries, adds headers (`X-Forwarded-For`, `traceparent`); costs more CPU.
- Behind a proxy, the client IP comes from `X-Forwarded-For`/`Forwarded` — trust it only from your own proxies.
- Long-lived connections (gRPC, WebSockets) stick to one backend; balance per request with L7 or client-side balancing.

<Pitfalls>

- **A new connection per request** — paying DNS + TCP + TLS every time.
- **No timeouts** (connect, read) on network calls.
- **Ignoring DNS TTLs** during migrations, or caching DNS forever in the JVM.
- **Trusting client-supplied `X-Forwarded-For`.**
- **Chatty protocols over high-latency links** — 50 sequential calls at 100 ms RTT is 5 seconds.
- **Confusing bandwidth with latency** — a bigger pipe doesn't shorten round trips.

</Pitfalls>

<KeyTakeaways>

- IP routes, ports identify processes, TCP makes streams reliable, TLS secures them.
- New connections cost round trips; reuse them with keep-alive and pools.
- HTTP/2 multiplexes; HTTP/3 (QUIC) removes TCP head-of-line blocking.
- DNS caching follows TTLs; L4 vs L7 balancers trade speed for HTTP awareness.

</KeyTakeaways>
