## Why it matters

Every request your service handles crosses a network, and many production problems are network problems in disguise. A slow first request is often a new connection being set up. Timeouts under load can be exhausted ports or pools. "Works by IP but not by name" is DNS. An app that is slow only for distant users is paying round trips. Knowing what each layer does tells you where the time goes and which setting to change.

This page follows one request from start to finish. Each layer then has its own page: [TCP and UDP](../tcp-and-udp/), [HTTP versions](../http-versions/), [DNS and TLS](../dns-and-tls/) and [real-time connections](../realtime-connections/).

<Callout type="analogy">
Sending a parcel. The street address is the IP address and the flat number is the port. The postal service (IP) moves boxes but may lose or reorder them. A courier with signatures and tracking (TCP) makes sure every box arrives, in order. A sealed, tamper-evident box is TLS. The phone book that turns a name into an address is DNS.
</Callout>

## The layers you actually deal with

| Layer | Protocols | What it gives you |
|---|---|---|
| Application | HTTP, gRPC, WebSocket, DNS | Meaning: requests, responses, messages |
| Security | TLS | Encryption, the server's identity, tamper detection |
| Transport | TCP, UDP, QUIC | Delivery to the right process; reliability with TCP and QUIC |
| Network | IP (v4 and v6) | Routing between machines across networks |
| Link | Ethernet, Wi-Fi | Delivery on the local network |

The OSI model has seven layers, but these five are the ones that show up in backend work. Each layer wraps the one above: an HTTP request sits inside TLS records, inside TCP segments, inside IP packets, inside Ethernet frames.

## Addresses, ports and NAT

- An **IP address** names a machine's network interface. IPv4 has about 4 billion addresses, which is not enough, so most devices sit behind NAT.
- A **port** (0 to 65535) names a process on that machine. Servers listen on well-known ports such as 443 for HTTPS. The client side gets a temporary **ephemeral port** for each connection.
- A TCP connection is identified by four values: source IP, source port, destination IP and destination port. That is why one client machine can only open about 28,000 connections at once to the same server address and port on default Linux settings: the ephemeral port range runs out.
- **NAT** (network address translation) lets many private addresses such as `10.0.0.5` share one public address. The router rewrites addresses and ports on the way out and remembers the mapping. Mappings expire when a connection is idle, which is why long-lived connections need keep-alive messages.

## What happens when you open a URL

<Walkthrough id="request-journey" />

<Diagram id="https-handshakes" caption="Round trips before the first byte of a new HTTPS request: DNS, TCP, TLS 1.3, then the request itself." />

The full story, in the order an interviewer expects it:

<Steps>

1. **Parse and check caches.** The browser parses the URL. HSTS may force `https`. A cached response, or a service worker, can answer without touching the network at all.
2. **DNS.** The name becomes an IP address, from the browser, OS or resolver cache, or by asking root, TLD and authoritative servers. See [DNS and TLS](../dns-and-tls/).
3. **TCP handshake** to port 443: SYN, SYN-ACK, ACK. One round trip. See [TCP and UDP](../tcp-and-udp/).
4. **TLS handshake**: agree keys and check the certificate. One more round trip with TLS 1.3. ALPN picks HTTP/2 or HTTP/1.1 in the same exchange.
5. **HTTP request and response.** Often a CDN or load balancer ends TLS and forwards the request to an application server, which reads caches and databases and responds.
6. **Render.** The browser parses HTML, finds CSS, scripts and images, fetches them over the same connection where it can, and draws the page.

</Steps>

HTTP/3 merges steps 3 and 4 into one round trip, because QUIC carries the TLS handshake. See [HTTP versions](../http-versions/).

## Latency is set by distance

Light in optical fibre travels at about two-thirds of its speed in a vacuum, roughly 200 km per millisecond. A round trip covers the distance twice, so every 100 km adds about **1 ms** of round-trip time, before any router, queue or server does anything. Real routes are longer than straight lines, so real numbers are higher.

So **latency** (time for one round trip) and **bandwidth** (bytes per second) are different limits. A faster link does not shorten a round trip. Fifty sequential API calls at 100 ms each take five seconds whatever the bandwidth. The fixes are fewer round trips: connection reuse, fewer sequential calls, and putting servers or a CDN closer to users.

## Load balancers and proxies

- **L4** (TCP or UDP) balancers route whole connections by address and port. They are fast and protocol-agnostic, but can't see HTTP paths or headers.
- **L7** (HTTP) balancers end TLS, route by host, path or header, retry, and add headers such as `X-Forwarded-For` and `traceparent`. They use more CPU.
- Behind a proxy, the client's address arrives in `X-Forwarded-For` or `Forwarded`. Trust it only when it was set by your own proxies, since clients can send it too.
- Long-lived connections (gRPC, WebSockets) stay on one backend for their whole life. See [real-time connections](../realtime-connections/) for what proxies do to them.

<Pitfalls>

- **A new connection per request**, paying DNS, TCP and TLS every time.
- **No timeouts** on network calls, so one slow dependency holds threads forever.
- **Trusting a client-supplied `X-Forwarded-For`** for rate limits or audit logs.
- **Chatty APIs over long distances.** Fifty sequential calls at 100 ms is five seconds.
- **Confusing bandwidth with latency.** A bigger pipe doesn't shorten a round trip.
- **Forgetting NAT and proxy idle timeouts**, which silently cut long-lived connections.

</Pitfalls>

<KeyTakeaways>

- IP routes between machines, ports pick the process, TCP makes a reliable stream, TLS secures it, HTTP gives it meaning.
- A new HTTPS connection costs about three round trips before the first byte; reuse connections.
- Each 100 km adds about 1 ms of round trip. Distance, not bandwidth, sets the floor.
- L4 balancers route connections, L7 balancers route requests.

</KeyTakeaways>
