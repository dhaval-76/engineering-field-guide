## Recognise it

- **Sorted** array and a pair/triple condition (sum, difference) → converging pointers.
- **Symmetry** (palindromes, reversing) → converging pointers.
- **Rearrange in place** with O(1) extra space (remove, deduplicate, move zeros, partition) → read/write pointers.
- Linked-list cycles and middles → fast/slow pointers ([Linked lists](../linked-lists/)).

<Callout type="analogy">
Two people searching a sorted bookshelf for two books whose page counts add up to 1,000: one starts at the thinnest, one at the thickest. Too many pages? The person at the thick end moves inward. Too few? The thin end moves. Neither ever needs to go back.
</Callout>

## Why converging works

On a sorted array with `sum = a[l] + a[r]`: if the sum is too small, no pair using `a[l]` with any element left of `r` can be large enough (they're all ≤ `a[r]`), so `l` can be discarded; symmetrically for too large. Every step safely eliminates one element, giving O(n).

<Pitfalls>

- **Using converging pointers on unsorted input** — the elimination argument needs order.
- **Duplicate results in k-sum** — skip equal values after sorting, at every level.
- **Off-by-one loop conditions** (`l < r` vs `l <= r`).
- **Moving both pointers** when only one can be safely discarded.
- **Sorting when indices must be returned** — keep original indices or use hashing.

</Pitfalls>

<KeyTakeaways>

- Converging pointers on sorted/symmetric data eliminate one candidate per step.
- Read/write pointers rearrange in place with O(1) space.
- Sort first to unlock the pattern; skip duplicates to avoid repeated answers.

</KeyTakeaways>
