## Recognise it

- "Return **all** subsets / permutations / combinations / partitions / valid arrangements."
- Constraint satisfaction: N-Queens, Sudoku, word search in a grid.
- Small n (≤ ~20) — a hint that exponential search is intended.
- If the question asks only for a **count** or **best value** and subproblems repeat, consider [dynamic programming](../dynamic-programming/) instead.

<Callout type="analogy">
Finding your way through a maze by trying a corridor, and when it dead-ends, walking back to the last junction and trying the next corridor. Chalk marks (the "unchoose" step) make sure you leave the maze as you found it for the next attempt.
</Callout>

| Problem | Branching | Size of the search |
|---|---|---|
| Subsets | include / exclude | 2ⁿ |
| Permutations | any unused element | n! |
| Combinations (k of n) | elements after the last pick | C(n, k) |
| N-Queens | safe columns in the next row | far fewer than nⁿ thanks to pruning |

<Pitfalls>

- **Forgetting to undo** a choice — state leaks into sibling branches.
- **Adding the live path** to results instead of a copy.
- **Duplicates** from repeated input values — sort and skip `nums[i] == nums[i−1]` at the same depth.
- **Weak pruning** — exploring branches that are already invalid.
- **Using backtracking for counting problems with overlapping subproblems** — exponential where DP would be polynomial.

</Pitfalls>

<KeyTakeaways>

- Backtracking = DFS over choices with undo.
- Subsets 2ⁿ, permutations n!, combinations C(n, k) — small inputs only.
- Prune early, skip duplicate siblings, and copy results.

</KeyTakeaways>
