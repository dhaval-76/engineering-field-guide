## Why it matters

Some questions have no shortcut: *list every valid arrangement*, *find any assignment that satisfies all constraints*. The answer itself may be exponential in size (a set of n items has 2ⁿ subsets), so no algorithm can avoid exploring a lot. Backtracking explores that space **systematically and without waste**: it builds a candidate one choice at a time, and abandons a partial candidate the moment it can't lead anywhere useful.

That abandoning — **pruning** — is the whole game. The same search can be hopeless or instant depending on how early invalid branches are cut. Backtracking powers Sudoku and constraint solvers, regex engines with backtracking semantics, game-tree search, configuration and scheduling tools, and test-case generators.

<Callout type="analogy">
Finding your way through a maze by trying a corridor, and when it dead-ends, walking back to the last junction and trying the next corridor. Chalk marks (the "unchoose" step) make sure you leave the maze exactly as you found it for the next attempt — and an experienced explorer doesn't even enter a corridor they can see is blocked.
</Callout>

## Recognise it

<Callout type="spot">

**Wording clues**

- "Return **all** subsets / permutations / combinations / partitions / valid arrangements."
- Constraint satisfaction: N-Queens, Sudoku, word search, placing items under rules.
- "Generate every valid…" (parentheses, IP addresses, phone-letter combinations).

**Constraint clues**

- **Small n** (≤ ~20 for subsets, ≤ ~10 for permutations) → an exponential search is intended.
- The output itself is exponential (all subsets of 20 items is 10⁶ lists) → no algorithm can be faster than listing them.

**Looks like it, but isn't**

- Only a **count** or the **best value**, and subproblems repeat → [dynamic programming](../dynamic-programming/); backtracking would recompute them exponentially often.
- A single valid choice at each step that never needs undoing → [greedy](../greedy/).

</Callout>

## The template

Backtracking is a <Term id="dfs">depth-first</Term> search over a **decision tree**: each level makes one choice, each node is a partial candidate, and leaves are complete candidates.

<Walkthrough id="subsets-tree" />

<CodeTabs id="dsa-backtrack-template" title="Choose → explore → unchoose" />

<Steps>

1. **Base case**: is the partial candidate complete (or a valid answer)? Record a **copy** of it.
2. **Choose**: for each option still allowed at this level, add it to the candidate.
3. **Explore**: recurse to the next level.
4. **Unchoose**: remove the option, restoring the state for the next sibling.

</Steps>

Three questions define any backtracking solution: *what is one choice?*, *which options are allowed next?*, and *when can I stop early?*

## Worked problems

### Subsets and permutations

<Clues>"**all** subsets" (2ⁿ) or "**all** orderings" (n!) with small n → backtracking: include/exclude, or pick any unused element.</Clues>

**Subsets**: at each element, include it or not — 2ⁿ leaves. Equivalently, every node of the "pick an element after the last one" tree is a subset. **Permutations**: at each position, any unused element — n! leaves; a `used[]` array makes "unused" O(1).

<CodeTabs id="dsa-subsets-permutations" title="Subsets and permutations" />

### Subsets with duplicates

**Problem.** `[1,2,2]` has 8 index-subsets but only 6 distinct ones.

<Clues>"all **distinct** subsets" with **repeated** values → sort, then skip a value equal to the previous one at the same depth.</Clues>

**Insight.** Sort, so equal values sit together. At one depth of the tree, choosing the first `2` or the second `2` as the next element produces exactly the same subtrees — so take only the **first** of equal siblings: skip `nums[i]` when `i > start` and `nums[i] == nums[i − 1]`. The same rule removes duplicates from permutations and combination sums.

<CodeTabs id="dsa-subsets-dup" title="Subsets II — skip equal siblings at the same depth" />

### Combination sum with pruning

**Problem.** Combinations of candidates (each usable repeatedly) that sum to a target.

<Clues>"**all** combinations that sum to target", values reusable → backtracking over sorted candidates, stopping once a value exceeds what remains.</Clues>

**Insight.** Pass a start index so combinations are generated in non-decreasing order (no `[2,3]` and `[3,2]` duplicates), and recurse with the **same** index to allow reuse. Sort the candidates so that the loop can **stop** — not just skip — as soon as one exceeds the remaining target: every later candidate is bigger.

<CodeTabs id="dsa-combination-sum" title="Combination sum — reuse allowed, prune on sorted input" />

### Generate parentheses

**Problem.** All balanced strings of n pairs of parentheses.

<Clues>"**all** valid strings" → build character by character, adding `(` while some remain and `)` only when one is open.</Clues>

**Insight.** Generating all 2²ⁿ strings and filtering is wasteful. Instead, only make choices that keep the prefix valid: add `(` while fewer than n are used, and `)` only while it would close an open one (`close < open`). Every leaf is then a valid answer — no dead ends at all. The count is the Catalan number (1, 1, 2, 5, 14, 42, …).

<CodeTabs id="dsa-generate-parentheses" title="Generate parentheses — choices that keep the prefix valid" />

### Word search in a grid

<Clues>"does a **path** in the grid spell the word?" + cells can't repeat → DFS from each cell, marking the current path and unmarking on return.</Clues>

**Insight.** Start a DFS from every cell matching the first letter; from a cell, try the four neighbours for the next letter. Mark cells on the **current path** so a letter isn't reused, and unmark them when backtracking (the path may pass through that cell later along a different route). Prune immediately when a cell doesn't match the next letter.

<CodeTabs id="dsa-word-search" title="Word search — grid DFS with in-place marking" />

To search **many** words at once in the same grid, put the words in a <Term id="trie">trie</Term> and walk the trie alongside the DFS ([Autocomplete / tries](../../low-level-design/autocomplete/)).

### N-Queens

<Clues>"**all** placements" under rules + n ≤ 9 → one queen per row; sets of used columns and diagonals make each check O(1).</Clues>

**Insight.** Place one queen per row (so rows never clash) and keep sets of used **columns** and both **diagonals**: cells on the same "\" diagonal share `row − col`, on the same "/" diagonal share `row + col`. Each safety check becomes O(1), and an unsafe column is never entered.

## Estimating the cost

| Problem | Branching | Size of the search | Practical limit |
|---|---|---|---|
| Subsets | include / exclude | 2ⁿ (× n to copy each) | n ≈ 20 |
| Permutations | any unused element | n! (× n) | n ≈ 10 |
| Combinations (k of n) | elements after the last pick | C(n, k) | depends on k |
| Generate parentheses | `(` or `)` while valid | Catalan(n) ≈ 4ⁿ / n^1.5 | n ≈ 12–14 |
| N-Queens | safe columns in the next row | far below n! with pruning | n ≈ 12–15 |

A useful sanity check before coding: 2²⁰ ≈ 10⁶ and 10! ≈ 3.6 × 10⁶ are fine; 2³⁰ ≈ 10⁹ and 13! ≈ 6 × 10⁹ are not.

## Talking through it in an interview

- Describe the decision tree: what one level decides, what the options are.
- Say how you avoid duplicates (start index, sorting and skipping equal siblings, `used[]`).
- Name your pruning rule and why it's safe.
- Give the output-sensitive complexity (2ⁿ · n for subsets) and the practical input limit.
- If they ask for a count or an optimum, check whether subproblems repeat — then switch to DP.

<Pitfalls>

- **Forgetting to undo** a choice — state leaks into sibling branches.
- **Adding the live path** to the results instead of a copy.
- **Duplicates** from repeated input values — sort and skip `nums[i] == nums[i−1]` when `i > start`.
- **`continue` where `break` is valid** — on sorted input, once a candidate is too big, all later ones are too.
- **Weak pruning** — checking constraints only at the leaves.
- **Backtracking for counting problems with overlapping subproblems** — exponential where DP would be polynomial.

</Pitfalls>

<KeyTakeaways>

- Backtracking = DFS over choices with undo: choose, explore, unchoose.
- Subsets 2ⁿ, permutations n!, combinations C(n, k) — small inputs only.
- Prune as early as possible; only make choices that can still succeed.
- Skip equal siblings to avoid duplicates; copy results when recording them.

</KeyTakeaways>
