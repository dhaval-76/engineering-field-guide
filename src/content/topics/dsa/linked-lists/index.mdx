## Why it matters

A linked list stores each element in its own node with a pointer to the next one. That costs memory and cache locality — an `ArrayList` is usually faster in practice — but it gives two abilities arrays don't: **O(1) insertion and removal anywhere you already hold a pointer**, and **re-linking in place** without copying. That's why linked lists sit inside an <Term id="lru">LRU</Term> cache, a free list in a memory allocator, the buckets of a hash map and the queue of runnable threads in an OS scheduler.

In interviews, linked lists test something specific: careful pointer manipulation under the constraint of **O(1) extra space**. The problems are rarely deep algorithmically; they are about never losing a node and handling the head, the tail and empty lists correctly. A handful of techniques — dummy heads, three-pointer reversal, fast/slow pointers and gap pointers — combine to solve nearly all of them.

<Callout type="analogy">
A treasure hunt where each clue tells you where the next one is. You can't jump to clue 50; you follow the chain. Re-linking means rewriting a clue — and if you overwrite it before reading where it pointed, the rest of the hunt is lost forever.
</Callout>

## Recognise it

<Callout type="spot">

**Wording clues**

- The input is a linked list, or a sequence defined by "next" pointers (including `i → nums[i]`, as in "find the duplicate number").
- The middle, a cycle, the k-th node from the end, merging, reversing a section, reordering.

**Constraint clues**

- "O(1) extra space" where copying to an array would be easy → pointer manipulation (fast/slow, in-place reversal).
- "Do not modify the values, only the links" → rewire `next` pointers.

**Looks like it, but isn't**

- Random access by index is needed often → an array or a deque; walking a list is O(n) per access.
- An LRU cache → a linked list **plus** a hash map ([Designing data structures](../design-data-structures/)), not a list alone.

</Callout>

## The four techniques

| Technique | What it does | Typical problems |
|---|---|---|
| **Dummy head** | a fake node before the head, so the real head is never a special case | merge, remove, partition, add numbers |
| **Three-pointer reversal** | `prev`, `cur`, `next`: save, re-point, advance | reverse list, reverse in k-groups, palindrome check |
| **Fast and slow pointers** | fast moves 2, slow moves 1 | middle, cycle detection, cycle start |
| **Gap pointers** | lead pointer starts n ahead | nth from end, rotate list |

## Reversing a list

<Walkthrough id="reverse-list" />

The loop keeps one invariant: `prev` is the head of the already-reversed part and `cur` is the head of the rest. Each step moves one node from the rest to the front of the reversed part — **save** `cur.next`, **re-point** `cur.next = prev`, **advance** both. When `cur` is null, `prev` is the new head.

The recursive version is elegant but uses O(n) stack space — a 100,000-node list can overflow the default Java thread stack.

## Fast and slow pointers

<CodeTabs id="dsa-cycle-detection" title="Floyd's cycle detection — has a cycle, and where it starts" />

- **Middle:** when fast reaches the end, slow has gone half as far.
- **Cycle detection:** inside a cycle, fast gains one step on slow per move, so it must catch up — they meet within one lap. Without a cycle, fast falls off the end.
- **Cycle start:** let the head be `a` steps from the cycle entry and the meeting point `b` steps into the cycle. Slow travelled `a + b`, fast `2(a + b)`; the difference `a + b` is a whole number of laps. So walking `a` more steps from the meeting point lands exactly on the entry — the same place a pointer starting at the head reaches after `a` steps. Move both one step at a time; they meet at the entry.

The same algorithm finds the duplicate in an array of n + 1 values in `[1, n]` without modifying it: treat `i → nums[i]` as next pointers; the duplicate is the cycle entry.

## Merging and gap pointers

### Merge two sorted lists

<Clues>**two sorted** lists + merge → a dummy head and a tail pointer.</Clues>

**Insight.** A dummy head plus a `tail` pointer: repeatedly attach the smaller head and advance. When one list runs out, attach the rest of the other in one step.

<CodeTabs id="dsa-merge-two-lists" title="Merge two sorted lists — dummy head" />

Merging **k** sorted lists uses a <Term id="heap">min-heap</Term> of the current heads — O(N log k) for N total nodes ([Heaps](../heaps-and-top-k/)).

### Remove the nth node from the end

<Clues>"n-th **from the end**" + one pass → two pointers n + 1 apart, from a dummy head.</Clues>

**Insight.** Start `lead` n + 1 nodes ahead of `trail` (both from a dummy). Move both until `lead` falls off the end; `trail` is then just before the node to remove. One pass, and the dummy handles removing the head itself.

## Combining techniques

### Reorder list

**Problem.** Rearrange `L0 → L1 → … → Ln` into `L0 → Ln → L1 → Ln−1 → …`, in place. `[1,2,3,4,5]` → `[1,5,2,4,3]`.

<Clues>"first, last, second, second-last…" + **in place** → find the middle (fast/slow), reverse the second half, merge.</Clues>

**Insight.** Three techniques in sequence: **fast/slow** to find the middle, **reverse** the second half (`[4,5]` → `[5,4]`), then **weave** the two halves together one node at a time. Each step is O(n) with O(1) space; using an array of nodes would be simpler but O(n) space — say both and let the interviewer choose.

<CodeTabs id="dsa-reorder-list" title="Reorder list — middle, reverse, weave" />

The same middle-and-reverse combination checks whether a list is a **palindrome** in O(1) space: reverse the second half and compare it with the first (and reverse it back if the caller needs the list intact).

### Add two numbers

**Problem.** Two numbers are stored as lists of digits, ones digit first. Return their sum as a list. `[2,4,3] + [5,6,4]` (342 + 465) → `[7,0,8]` (807).

<Clues>digits stored **ones first** → add digit by digit with a carry, like on paper, building the result behind a dummy head.</Clues>

**Insight.** It's grade-school addition: walk both lists together with a carry. The loop continues while **either** list has nodes **or** a carry remains, which handles different lengths and a final carry (`999 + 1`) without special cases. Because nothing is converted to an integer, numbers of any length work — no overflow.

<CodeTabs id="dsa-add-two-numbers" title="Add two numbers — digit by digit with a carry" />

If the digits are stored most-significant first, reverse both lists first (or push digits onto two stacks), add, and build the result from the front.

## Complexity at a glance

| Problem | Time | Extra space |
|---|---|---|
| Reverse | O(n) | O(1) iterative, O(n) recursive |
| Cycle detection / start | O(n) | O(1) |
| Middle | O(n) | O(1) |
| Merge two sorted | O(m + n) | O(1) |
| Merge k sorted | O(N log k) | O(k) |
| Remove nth from end | O(n), one pass | O(1) |
| Reorder list | O(n) | O(1) |
| Add two numbers | O(max(m, n)) | O(1) besides the output |

## Talking through it in an interview

- Draw three or four boxes and arrows before writing code, and step through one iteration on the drawing.
- Name the technique ("I'll use a dummy head so removing the first node isn't a special case").
- Check the edge cases out loud: empty list, one node, two nodes, n equal to the length.
- Ask whether you may modify the input list; restore it if needed (palindrome check).

<Pitfalls>

- **Losing the rest of the list** — save `next` before changing `cur.next`.
- **Null checks for fast pointers** — `fast != null && fast.next != null` (or `fast.next.next` when you want the first middle).
- **Special-casing the head** — a dummy node avoids it.
- **Returning the wrong head** after reversal (it's `prev`, not `head`).
- **Forgetting to cut the list** before weaving halves — the result loops forever.
- **Recursive solutions on long lists** — stack overflow; prefer iteration.

</Pitfalls>

<KeyTakeaways>

- Dummy heads, three-pointer reversal, fast/slow and gap pointers cover most list problems; hard ones combine them.
- Floyd's algorithm detects cycles and finds their start in O(1) space.
- Draw before coding; preserve `next` before re-linking; cut lists before weaving.

</KeyTakeaways>
