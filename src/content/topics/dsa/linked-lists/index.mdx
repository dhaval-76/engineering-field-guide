## Recognise it

- Input is a linked list, or a sequence defined by "next" pointers (including functional graphs like `i → nums[i]`).
- Needs O(1) extra space where an array copy would be easy.
- Middle, cycle, kth from end, merge, reverse a section.

<Callout type="analogy">
A treasure hunt where each clue tells you where the next one is. You can't jump to clue 50; you follow the chain. Re-linking means rewriting a clue — and if you overwrite it before reading it, the rest of the hunt is lost.
</Callout>

Why the cycle start works: if the head is `a` steps from the cycle entry and they meet `b` steps into the cycle, slow travelled `a + b` and fast `2(a + b)`; the difference `a + b` is a multiple of the cycle length, so walking `a` more steps from the meeting point lands on the entry — exactly where a pointer from the head arrives after `a` steps.

<Pitfalls>

- **Losing the rest of the list** — save `next` before changing `cur.next`.
- **Null checks for fast pointers** — `fast != null && fast.next != null`.
- **Special-casing the head** — a dummy node avoids it.
- **Returning the wrong head** after reversal (it's `prev`, not `head`).
- **Modifying input lists** when the caller still needs them.

</Pitfalls>

<KeyTakeaways>

- Dummy heads, three-pointer reversal, fast/slow and gap pointers cover most list problems.
- Floyd's algorithm detects cycles and finds their start in O(1) space.
- Draw before coding; preserve `next` before re-linking.

</KeyTakeaways>
