## Recognise it

- "X must happen before Y": courses and prerequisites, build targets, package installs, spreadsheet cell recalculation, task pipelines.
- "Is it possible to finish everything?" → cycle detection in a directed graph.
- "Give a valid order" / "minimum number of semesters" → topological order / Kahn's levels.

<Callout type="analogy">
Getting dressed: socks before shoes, trousers before shoes and belt, shirt before tie. Any order respecting those arrows works. If someone insisted shoes before socks *and* socks before shoes, you'd never get dressed — that's a cycle.
</Callout>

## DFS with three colours

White = unvisited, grey = on the current DFS path, black = finished. Reaching a grey node means a back edge — a cycle. Appending each node when it turns black and reversing gives a topological order.

| Problem | Graph | Answer |
|---|---|---|
| Can all courses be finished? | prerequisite → course | Kahn's processed count == n |
| Course order | same | Kahn's output |
| Minimum semesters (parallel) | same | number of Kahn's levels |
| Alien dictionary | first differing letters of adjacent words | topological order of letters |
| Build order / package manager | dependency → dependent | topological order; cycle = error |

<Pitfalls>

- **Reversed edges** (`course → prerequisite`) — the order comes out backwards.
- **Forgetting nodes with no edges** — they still belong in the order.
- **Undirected cycle detection logic** applied to directed graphs (visited alone isn't enough; you need "in progress").
- **Alien dictionary edge case**: a word followed by its own prefix (`"abc"` before `"ab"`) is invalid.
- **Recursion depth** in DFS on long chains.

</Pitfalls>

<KeyTakeaways>

- Topological orders exist exactly for DAGs.
- Kahn's (in-degrees, BFS) also detects cycles and gives parallel levels.
- DFS three-colour: grey-to-grey edge = cycle; reverse post-order = topological order.

</KeyTakeaways>
