## Recognise it

- **Nesting and matching**: brackets, tags, nested encodings (`3[a2[c]]`), function calls → plain stack.
- "For each element, the **next/previous greater or smaller**" — temperatures, stock spans, histogram areas, "how far can this bar extend?" → monotonic stack.
- Iterative DFS or undo history → stack.

<Callout type="analogy">
A stack of plates: you only ever take the top one. A monotonic stack is a queue of people at a parade, each blocking the view of everyone shorter behind them — when a tall person arrives, everyone shorter in front of them "sees" their next taller person and leaves.
</Callout>

### Largest rectangle in a histogram

For each bar, the widest rectangle using its height extends until the nearest shorter bar on each side. An increasing stack finds both boundaries: when a shorter bar arrives, the popped bar's right boundary is the current index and its left boundary is the new stack top.

<CodeTabs id="dsa-largest-rectangle" title="Largest rectangle in histogram — increasing stack, O(n)" />

| Want | Stack order (bottom → top) | Pop when |
|---|---|---|
| next greater element | decreasing | new value > top |
| next smaller element | increasing | new value < top |
| previous greater | decreasing | read the top after popping smaller-or-equal |

<Pitfalls>

- **Popping an empty stack** — check before popping (unbalanced closers).
- **Leftover items** at the end — they have no next greater element (or, for histograms, extend to the end; use a sentinel height 0).
- **Strict vs non-strict comparisons** with equal values — decide which side "owns" ties.
- **Storing values when widths need indices.**
- **`java.util.Stack`** — synchronized and extends Vector; prefer `ArrayDeque`.

</Pitfalls>

<KeyTakeaways>

- Stacks resolve "most recent unmatched" structures.
- Monotonic stacks answer nearest-greater/smaller questions in O(n).
- Keep indices; use sentinels to flush the stack at the end.

</KeyTakeaways>
