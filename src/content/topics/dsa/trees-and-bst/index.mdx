## Recognise it

- Input is a tree (or a hierarchy: org charts, file systems, expression trees).
- The answer for a node depends on its children's answers → **post-order recursion**.
- The answer depends on the path from the root → **pass state down** (pre-order).
- "By level", "right side view", "minimum depth" → **BFS**.
- Sorted order, k-th smallest, range queries → **BST** properties.

<Callout type="analogy">
A company asking "how many people work under each manager?" Every manager asks their direct reports for their counts, adds them up and adds one for themselves — the question flows down, the answers flow back up. That's post-order recursion.
</Callout>

## Lowest common ancestor

<CodeTabs id="dsa-lca" title="Lowest common ancestor — general tree and BST" />

| Problem | Technique | Complexity |
|---|---|---|
| Max depth, balanced check, diameter | post-order, return heights | O(n) |
| Path sum, root-to-leaf paths | pre-order, pass remaining sum down | O(n) |
| Level order, right side view | BFS by level | O(n) |
| Validate BST | bounds passed down | O(n) |
| k-th smallest in BST | in-order, stop at k | O(h + k) |
| LCA | post-order "found in left/right" | O(n); O(h) in a BST |

<Pitfalls>

- **Validating a BST by comparing only with the parent** — a deep node can violate an ancestor's bound.
- **Missing base cases** (`null` children).
- **Recomputing heights** at every node (O(n²)) instead of returning them up.
- **Recursion depth** on degenerate trees (a "linked list" of 10⁵ nodes) — use iteration.
- **Integer bounds** when values can equal `Integer.MIN_VALUE` — use `null` or `long` bounds.

</Pitfalls>

<KeyTakeaways>

- Define the answer recursively: what do children return, what does the node combine?
- Post-order for bottom-up values; pre-order for top-down state; BFS for levels.
- BST invariants are about whole subtrees: pass bounds; in-order is sorted.

</KeyTakeaways>
