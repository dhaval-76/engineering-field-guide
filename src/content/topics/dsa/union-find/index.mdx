## Recognise it

- "Are x and y connected?" asked many times while connections keep being **added**.
- Count **groups/components** after a list of merges (friends circles, accounts with shared emails, islands added over time).
- Find the edge that creates a **cycle** in an undirected graph.
- Build a **minimum spanning tree**.

<Callout type="analogy">
Clubs merging. Every member knows who their club's president is (directly or via someone who does). To check if two people are in the same club, ask for their presidents. To merge two clubs, one president agrees to report to the other. After you ask "who's my president?" once, you remember the answer directly next time — path compression.
</Callout>

| Question | Union-find | BFS/DFS |
|---|---|---|
| Components of a fixed graph | O(E α(V)) | O(V + E) — just as good |
| Connectivity while edges are added online | near O(1) per edge | re-traverse each time |
| Edges removed over time | not supported (process offline in reverse) | works |
| Cycle in undirected graph | union returns false | DFS with parent tracking |
| Directed graphs / cycles | not suitable | DFS (three colours) |

<Pitfalls>

- **Comparing `parent[a] == parent[b]`** instead of `find(a) == find(b)`.
- **Skipping union by rank/size and path compression** — degenerates to O(n) per find.
- **Recursive find on long chains** before compression — use the iterative two-pass version for huge inputs.
- **Using union-find for directed cycles** — it ignores direction.
- **Forgetting to count components** down on each successful union.

</Pitfalls>

<KeyTakeaways>

- `find` with path compression, `union` by size/rank: effectively O(1) per operation.
- A failed union reveals a cycle; successful unions reduce the component count.
- Best for incremental connectivity and Kruskal's MST; use DFS for directed graphs.

</KeyTakeaways>
