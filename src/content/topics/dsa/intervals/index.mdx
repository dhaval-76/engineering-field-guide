## Recognise it

- Input is a list of `[start, end]` pairs: meetings, reservations, ranges.
- Questions: merge overlaps, insert a new range, minimum removals to avoid overlap, how many resources at once, free gaps.

<Callout type="analogy">
A shared calendar. To merge busy blocks, read them in order of start time and extend the current block while the next one starts before it ends. To count how many rooms you need, walk through the day and note how many meetings are running at each moment — the peak is the answer.
</Callout>

### Keep the most non-overlapping intervals

To remove the fewest intervals, keep as many as possible: sort by **end** and greedily take each interval that starts after the last kept one ends. Finishing early leaves the most room for the rest.

### How many rooms?

<CodeTabs id="dsa-meeting-rooms" title="Minimum meeting rooms — min-heap of end times, and sweep line" />

| Problem | Sort by | Technique |
|---|---|---|
| Merge intervals | start | extend current end |
| Insert interval | (already sorted) | three phases: before, overlapping, after |
| Max non-overlapping / min removals | end | greedy earliest finish |
| Min rooms / max overlap | start (heap) or event time (sweep) | min-heap of ends / ±1 events |
| Intersections of two lists | (both sorted) | two pointers |

<Pitfalls>

- **Sorting by end when merging** (or by start for max non-overlapping) — the greedy argument breaks.
- **Touching endpoints** — `[1,2]` and `[2,3]`: overlapping for merging in most problems, not for meetings (a room frees at 2).
- **Mutating input intervals** that the caller still uses.
- **Sweep-line tie order** — process ends before starts at the same time when touching isn't overlap.

</Pitfalls>

<KeyTakeaways>

- Sort first: by start for merging, by end for maximum selection.
- Max simultaneous overlap = rooms needed: heap of ends or ±1 sweep.
- Pin down the endpoint convention before coding.

</KeyTakeaways>
