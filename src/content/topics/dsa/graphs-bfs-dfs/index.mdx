## Why it matters

A graph is the most general way to describe **things and the connections between them**: users and follows, services and calls, cities and roads, packages and dependencies, web pages and links, states of a puzzle and the moves between them. Once a problem is drawn as a graph, a small toolbox answers a huge range of questions — *is B reachable from A? what is the fewest number of steps? how many separate groups are there? is there a cycle?*

**Breadth-first search** and **depth-first search** are that toolbox's foundation. Both visit every vertex and edge once — O(V + E) — and differ only in order: BFS fans out by distance (a queue), DFS dives as deep as possible first (a stack or recursion). <Term id="dijkstra">Dijkstra</Term>, <Term id="topological-sort">topological sort</Term>, cycle detection, flood fill and web crawlers are all built on them.

<Callout type="analogy">
BFS is a stone dropped in a pond: ripples reach everything at distance 1, then 2, then 3 — so the first time a ripple touches the shore is the shortest distance. DFS is a maze explorer who follows one corridor to its end before <Term id="backtracking">backtracking</Term> to try the next turning.
</Callout>

## Recognise it

<Callout type="spot">

**Wording clues**

- Things connected to other things: friends, cities, courses, words that differ by one letter.
- A **grid** where you move up/down/left/right: islands, mazes, flood fill, spreading (rotting oranges, fire).
- "**Minimum number of steps/moves**" where every move costs the same → BFS.
- "Count groups", "is X reachable", "does a cycle exist", "list all paths" → DFS (or BFS).
- A puzzle with **states and moves** (word ladder, open the lock, sliding puzzle) → BFS over an implicit graph.

**Constraint clues**

- A grid of m × n up to ~10⁶ cells → each cell is a node; BFS/DFS in O(m · n).
- V and E up to 10⁵ → adjacency lists and O(V + E); an adjacency matrix (V²) would be too big.
- Deep grids (10⁶ cells) → recursive DFS can overflow the stack; use an explicit stack or BFS.

**Looks like it, but isn't**

- Moves with **different costs** → [shortest paths](../shortest-paths/) (Dijkstra), not plain BFS.
- "Valid order respecting dependencies" → [topological sort](../topological-sort/).
- Only merging groups and asking "same group?" as edges arrive → [union-find](../union-find/).

</Callout>

## Representing a graph

<CodeTabs id="dsa-graph-build" title="Adjacency list from an edge list, and grid neighbours" />

| Representation | Space | Edge check | Iterate neighbours | Use when |
|---|---|---|---|---|
| Adjacency list | O(V + E) | O(degree) | O(degree) | sparse graphs — almost always |
| Adjacency matrix | O(V²) | O(1) | O(V) | dense graphs, small V |
| Implicit (grid, rule) | none | compute | compute | grids, word ladders, state spaces |

Real-world graphs are almost always sparse (a user follows hundreds of accounts, not millions), which is why adjacency lists are the default.

## BFS: shortest paths by number of steps

BFS keeps a queue and processes it in order. Everything at distance 1 is dequeued before anything at distance 2, so the **first time** a node is reached is along a shortest path. Mark a node visited **when you enqueue it**, not when you dequeue it — otherwise the same node can be enqueued by several neighbours and the queue grows far beyond V.

## DFS: components and reachability

DFS follows one neighbour as deep as possible, then backtracks. To count connected components (islands), start a DFS from every unvisited cell; each start discovers one whole component.

<CodeTabs id="dsa-number-of-islands" title="Number of islands — DFS flood fill (recursive and iterative)" />

Recursive DFS on a 1000 × 1000 grid can recurse a million levels deep and overflow the stack; the iterative version with an explicit stack (or BFS) avoids that.

## Multi-source BFS

<Clues>"minutes until **all**…" spreading from **many** starting cells at once → BFS with every source in the queue at distance 0.</Clues>

**Insight.** When there are many starting points (all rotten oranges, all exits, all servers), put **all of them** in the queue at distance 0. The BFS then computes, for every node, the distance to its **nearest** source in a single O(V + E) pass — instead of one BFS per source.

## Two-colouring: is the graph bipartite?

**Problem.** Can the nodes be split into two groups so that every edge goes between groups? (Teams with no rivals in the same team; scheduling exams so no student has two at once in a two-slot day.)

<Clues>"split into **two groups** so every edge crosses" → colour with BFS/DFS; an edge between two same-coloured nodes means no.</Clues>

**Insight.** Colour the start node, give each neighbour the opposite colour, and continue by BFS. If an edge ever connects two nodes of the **same** colour, the graph contains an odd cycle and can't be split. Restart from every uncoloured node, because the graph may be disconnected.

## Implicit graphs: word ladder

**Problem.** The fewest words in a chain from `hit` to `cog`, changing one letter at a time, using only words from a list. `[hot,dot,dog,lot,log,cog]` → 5 (`hit → hot → dot → dog → cog`).

<Clues>"**fewest** changes from one word to another", each change costs the same → BFS over words, neighbours differ by one letter.</Clues>

**Insight.** The graph isn't given — nodes are words and edges join words one letter apart. Building all edges up front compares every pair (O(N² · L)). Instead, **generate neighbours on the fly**: for each position, try all 26 letters and keep the results that are in the word set. BFS level by level gives the fewest steps. Removing a word from the set when it's enqueued doubles as the visited marker.

<CodeTabs id="dsa-word-ladder" title="Word ladder — BFS over generated neighbours" />

**Optimisation:** bidirectional BFS — search from both ends and stop when the frontiers meet — explores roughly 2·b^(d/2) nodes instead of b^d.

## Cycles

<Clues>"does a **cycle** exist?" → undirected: a visited neighbour that isn't your parent; directed: a node still on the current DFS path.</Clues>

- **Undirected graph:** during DFS, reaching an already-visited node that isn't the node you came from means a cycle (or use union-find: an edge whose ends are already in the same set closes a cycle — [Union-find](../union-find/)).
- **Directed graph:** a cycle exists when DFS reaches a node that is still **on the current path** (colour it "in progress" until its DFS finishes) — the basis of [topological sort](../topological-sort/).

## Complexity at a glance

| Problem | Algorithm | Time | Space |
|---|---|---|---|
| Fewest steps (unweighted) | BFS | O(V + E) | O(V) |
| Connected components / islands | DFS or BFS | O(V + E), grid O(R·C) | O(V) |
| Nearest of many sources | multi-source BFS | O(V + E) | O(V) |
| Bipartite check | BFS two-colouring | O(V + E) | O(V) |
| Word ladder | BFS, generated neighbours | O(N · L · 26) | O(N · L) |
| Clone graph | DFS/BFS + map | O(V + E) | O(V) |

## Talking through it in an interview

- Say what the nodes and edges are ("each cell is a node; edges to its four neighbours").
- Choose BFS or DFS out loud and say why ("fewest moves, equal costs → BFS").
- Mention the visited set and when you mark it.
- Give O(V + E) — and translate it for grids (rows × cols) or implicit graphs (states × moves per state).
- For large grids, mention recursion depth and offer the iterative version.

<Pitfalls>

- **Marking visited when dequeuing** in BFS — nodes are enqueued many times.
- **No visited set** on graphs with cycles — infinite loops.
- **Recursive DFS on large grids** (10⁶ cells) — stack overflow; use an explicit stack or BFS.
- **Mutating the input grid** to mark visited when the caller needs it intact.
- **Forgetting disconnected parts** — start a traversal from every unvisited node.
- **BFS on weighted graphs** — it finds the fewest edges, not the cheapest path; use Dijkstra ([Shortest paths](../shortest-paths/)).

</Pitfalls>

<KeyTakeaways>

- Adjacency lists for real graphs; neighbours computed on the fly for grids and state spaces.
- BFS = fewest steps with equal costs; DFS = exploration, components, cycles.
- Mark visited when enqueuing; start from every unvisited node; multi-source BFS for "nearest of many".
- Two-colouring tests bipartiteness; both traversals are O(V + E).

</KeyTakeaways>
