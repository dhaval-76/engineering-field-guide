## Recognise it

- Things connected to other things: friends, cities, courses with prerequisites, words differing by one letter.
- A **grid** where you can move up/down/left/right: islands, mazes, flood fill.
- "**Minimum number of steps/moves**" with equal-cost moves → BFS.
- "Count groups", "is X reachable", "does a cycle exist" → DFS (or BFS, or union-find).

<Callout type="analogy">
BFS is a stone dropped in a pond: ripples reach everything at distance 1, then 2, then 3 — so the first time a ripple touches the shore is the shortest distance. DFS is a maze explorer who follows one corridor to its end before backtracking to try the next.
</Callout>

<Pitfalls>

- **Marking visited when dequeuing** in BFS — the same node is enqueued many times.
- **No visited set** on graphs with cycles — infinite loops.
- **Recursive DFS on large grids** (10⁶ cells) — stack overflow; use an explicit stack or BFS.
- **Mutating the input grid** to mark visited when the caller needs it intact.
- **BFS on weighted graphs** — it only finds fewest edges; use Dijkstra for weights ([Shortest paths](../shortest-paths/)).

</Pitfalls>

<KeyTakeaways>

- Adjacency lists for real graphs; neighbours computed on the fly for grids.
- BFS = shortest path in steps; DFS = exploration, components, cycles.
- Visited sets prevent repeats; multi-source BFS handles "nearest of many".
- O(V + E) for both.

</KeyTakeaways>
